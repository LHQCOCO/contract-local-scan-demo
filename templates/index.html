自定义规则

        
面向涉及保密或特殊合规岗位的审阅场景，企业规章、内部审查清单、地方制度与他国法典均可直接导入：条文进知识库，规范句并列成规则，数值口径自动接管阈值。全程本机处理，来源可溯，停用即回退。

      

      

        
      

    


    

      

        ① 法条层 · 依据
        导入的条文（法典 / 地方制度 / 企业规章）按条切分进入知识库，参与检索并被规则引用为出处。法条层只做依据，不直接下结论。
      

      

        ② 规则层 · 判断
        「禁止 / 应当」类规范句自动派生为检查规则，与内置规则并列产出风险结论。同一条款内置与自定义结论不同时，双方并列展示并附出处，由专业人士判定。
      

      

        ③ 阈值层 · 口径
        「违约金不得超过 X%」这类数值口径句会接管对应的内置阈值参数，接管来源在「系统与隐私 → 规则阈值」中标注；停用规则包即回退为原值。

高频疑问

        

          
规则命中很少，是不是没有生效？规则按条款特征匹配，命中数量与合同规范程度成反比：条款越接近示范文本、表述越完整，命中就越少。判断引擎是否正常执行，看三处即可——报告「关键条款」是否抽出了甲乙方、金额、期限；「风险清单」每条是否附有触发原因与对应法条；「规则引擎与本地模型」页显示的实际规则条数是否与当前版本一致。三项均正常，说明引擎已完整执行。只有当关键条款为空、风险清单为 0 条同时出现时，才需要检查文件解析是否成功，例如纯图片 PDF 是否超出 30 页上限、扫描质量是否过低。


          
规则提示了风险，但我认为条款没有问题，怎么处理？规则命中的含义是「此处符合风险特征，值得复核」，不是「此处必然违法」。处理方式是逐条阅读触发原因与所附法条：若法条适用于本合同的类型与场景，按修订草案评估是否需要调整；若法条与本合同类型不匹配（例如技术开发合同被按采购合同的质量检验规则命中），可以直接忽略。工具不对人工判断做记录，若导出报告需要供内部流转或对外谈判，建议在报告之外另行备注采纳与不采纳的理由。


          
风险分数能不能跨合同比较？分数衡量的是风险密度，即命中规则的加权数量与合同篇幅的比值，不是法律风险的绝对值。同类合同（如同一模板下的多份劳动合同、同一供应商的多份采购合同）横向比较有意义，可据此判断哪一份更需要修改；不同类型的合同规则组不同、条款结构不同，分数不具备可比性。跨合同比较应限定在同一合同类型、同一规则开关配置下进行。


          
同一份合同审两次，结果为什么不一样？审阅本身是确定性的：解析文本与规则集合一致时，结果一致。出现差异通常是两个原因。其一是两次之间改动了行业开关或规则阈值，参与比对的规则发生变化。其二是两次的字段抽取来源不同，一次启用了本地模型、另一次模型不可用而降级为纯规则，依赖字段的风险判断随之改变。若需要严格对比两次结果，请保持规则开关与模型设置一致。


          
合同里明明写了金额，「关键条款」里的金额却是空的？字段抽取依赖明确的表述结构，例如「合同总金额为人民币 X 元」「价款：X 元」。以下写法容易抽取失败：金额以大写中文书写（如「壹拾万元整」）、金额分散在附件或表格中、金额以「单价×数量」或公式表达、金额出现在图片里。启用本地模型可以显著提高这些情况下的抽取率；仍然失败时，在导出前人工补记即可，不影响风险规则的执行。


          
扫描件识别出来的文字有缺行，能直接使用吗？需要人工比对后再使用。本地 OCR 对清晰、正向、无手写的扫描件识别率较高，但倾斜拍摄、光照不均、印章覆盖文字、多栏排版、竖排文字等情况会漏行或产生错字。识别结果直接作为规则比对的输入，缺行意味着该处条款可能未被命中。建议在导出前对照原文核对「关键条款」与「风险清单」引用的原文片段；涉及重要权益的合同，优先改用原始电子文档（DOCX 或文字版 PDF）。


          
审阅内容和审阅报告会离开这台电脑吗？不会。解析、抽取、规则比对、法规检索、报告生成全部在本机完成，导出文件写入本机指定目录。应用运行期间有外联监测，任何指向本机之外的连接都会被记录并拦截，也可手动进入锁定模式彻底断开外网，本机模型与回环连接不受影响。本地模型通过 127.0.0.1 与本机 Ollama 通信，属于回环连接，不经过外部网络。唯一的联网行为发生在自行安装 Ollama、下载模型权重的过程中，该过程与合同内容无关。


          
更换电脑后，历史记录能带走吗？可以，但需要手动迁移。审阅记录保存在数据目录 ~/Library/Application Support/ContractLocalScan 下的 SQLite 数据库中，该目录不随应用本体移动。将整个数据目录拷贝到新机器的同一路径，再启动应用，历史记录即可延续。若在旧机器上执行过「一键卸载与清理」，数据已删除，无法恢复。


          
一次审阅多份合同，为什么总耗时接近单份的倍数？多份合同在同一进程内顺序处理，不并行执行。这样设计是为了避免多份合同同时占用模型与内存，导致超时或抽取失败，也便于逐份显示进度。启用本地模型时，8 份合同的总耗时约为单份耗时的 8 倍；若只需快速筛查，可关闭「模型增强」，纯规则模式下每份约 1 秒完成。


          
修订草案能直接替换原文吗？草案是基于规则模板生成的替换建议，用于说明「改成什么样更稳妥」，不是最终定稿。替换前需要确认三件事：草案是否保留了你的商业意图（例如下调违约金比例后是否仍具备约束力）、是否与本合同其他条款冲突（例如与争议解决条款的约定不一致）、是否在对方可接受范围内。草案的价值在于提供一个有法条依据的谈判起点，不能替代执业律师对具体交易的判断。


          
关闭「模型增强」后，之前的结果会受影响吗？不会。模型只参与字段抽取，风险判定由规则引擎完成。关闭模型后新发起的审阅改用规则抽取字段，已保存的历史记录与已导出的报告内容不变。两种模式下的风险规则完全一致，差别仅在于抽取不准导致的字段缺失，可能间接影响少数依赖字段的规则是否被触发。

阈值

        
违约金 30%、定金 20%、竞业 24 个月这类默认值本身就是法定红线，一般不要改动。确有内部标准（例如公司要求违约金上限 28%）时，到「系统与隐私 → 规则与扩展 → 规则阈值」修改对应数值，保存后下次审阅生效，无需修改配置文件，也无需重启应用。

工具如何运行

        
Contract LocalScan 是完全在本机运行的合同预审工具，合同文件与审阅结果只保存在本机 SQLite 数据库，审阅过程中不发起任何网络请求。一次审阅依次经过「解析 → 抽取 → 研判 → 存证」四个阶段，由三个本地组件协同完成：规则引擎逐条比对法定阈值与行业条款，本地模型从非结构化文本中抽取关键字段，本地法规知识库为每条命中的风险提供法条原文依据。模型不可用时自动降级为纯规则模式，审阅不会中断。

        

          
功能模块说明

          
合同解析支持 PDF / DOCX / TXT；纯图片 PDF 走本地 OCR 识别文字，单份最多处理 30 页，超出部分不识别，需拆分后分别上传。单次最多 8 份、单份不超过 25 MB。

          
条款抽取抽取甲乙方、合同金额、履行期限、付款方式、违约责任等结构化字段。开启本地模型时由模型抽取，关闭时由规则与版式推断。

          
风险研判191 条规则（通用 + 8 个行业）逐条比对，命中项分级评分，并附上对应法条与可直接替换的修订草案。

          
法规知识库内置 63,653 条法规（1,474 部中国规范文本 + 6 项国际规则），采用本地 BM25 检索，可独立查询原文。审阅报告引用的每条法条均出自此处。

          
本地模型可选增强，使用本机 Ollama 的推荐模型（qwen2.5:3b 或 gemma3:4b，按本机内存选择）抽取字段。模型离线、未安装或内存不足时自动降级为纯规则模式，不影响审阅。

          
历史记录审阅结果写入本机 SQLite，可在「历史记录」中随时回看，也能对同一次审阅重复导出，不必重新扫描。

          
外联监测运行期记录并拦截任何指向本机之外的连接，可一键断联锁死外网，本机模型与回环连接不受影响。

          
导出三种产物：审阅报告 PDF（含风险清单与法条依据）、字段清单 Excel（结构化字段表）、批注版合同（在原合同上标注风险点）。

        


        
格式与限制

        
支持 PDF / DOCX / TXT 三种格式。单次最多 8 份，单份不超过 25 MB。超过数量或体积会直接拒收并给出提示，不会静默截断。

        
加密带密码的 PDF、扩展名与实际格式不符的文件会解析失败，请先解除密码或另存为标准格式。.doc 老格式需要先在 Word 中另存为 .docx。


        
导出

        
三种产物：审阅报告 PDF（含风险清单与法条依据）、字段清单 Excel（结构化字段表）、批注版合同（在原合同上标注风险点）。保存方式两种，导出文件内容完全相同，只是保存位置的决定方式不同。

        

          
模式行为

          
直接保存不弹窗，直接写入「导出文件保存目录」。同名文件自动追加序号，不会覆盖。导出完成后按钮旁会出现「在访达中显示」，点一下即可定位文件。

          
浏览器下载每次弹出系统保存对话框，由你选择位置和文件名。适合临时导出到 U 盘或共享文件夹。

        

        
默认目录 ~/Desktop/ContractLocalScan-导出，可在「系统与隐私」中改成任意可写目录。如果导出后找不到文件，先确认该目录是否存在且有写入权限——目录被删除或指向只读位置时，导出会失败并提示。


        
本地模型连不上怎么办

        
「系统与隐私 → 本地模型」里的「自检与修复」只覆盖两种最常见情况：Ollama 服务没启动、所需模型没下载。点完修复仍然失败，按下面的顺序逐项检查，多数问题能定位到具体一条。

        
关于「终端」：下面出现的命令都要在 macOS 的「终端」里执行。打开终端的方法：按 ⌘ + 空格，输入「终端」两个字后回车。每条命令输入完按一下回车就会执行，看到提示符 $ 重新出现才算结束。


        

          
1是否装了 Ollama

          
先确认电脑上有没有安装 Ollama。在终端输入下面这行后回车：

          
ollama -v

          

            
正常输出类似 ollama version is 0.3.12（带版本号），说明已安装，继续第 2 项。

            
异常出现 zsh: command not found: ollama（中文系统可能显示「找不到命令」），说明没装。

          

          
怎么处理：到 ollama.com 下载 macOS 版，双击下载到的 .pkg 文件按提示安装。装完关掉终端窗口、再重开一个新的，重新执行 ollama -v，确认能看到版本号。

        


        

          
2服务是否在运行

          
Ollama 装了不等于服务在跑。下面这条命令会向本机 11434 端口的 Ollama 服务请求模型列表，根据返回结果判断服务状态：

          
curl http://127.0.0.1:11434/api/tags

          

            
正常立刻返回一串以 {"models":[...]} 开头的内容，说明服务在跑，继续第 3 项。

            
异常终端卡住几秒后出现 curl: (7) Failed to connect to 127.0.0.1 port 11434: Connection refused（中文可能显示「连接被拒绝」），或者一直没任何输出，说明服务没起来。

          

          
怎么处理（任选一种）：

          
    
            
  • 在终端输入 ollama serve 回车，窗口会停住、不再出现 $ 提示符——这是正常的，保持这个窗口开着不要关。
    • 
            
  • 打开「访达 → 应用程序」，找到 Ollama 图标双击打开；屏幕右上角菜单栏出现一只小羊图标，即表示服务已启动。
    • 
          

        


        

          
3模型是否已下载

          
服务在跑，但还需要把具体模型下载到本机。输入下面这行列出已下载的模型：

          
ollama list

          

            
正常输出一张表，NAME 列里有 qwen2.5:3b（或你在设置页选中的那个模型），说明就绪，跳到第 4 项。

            
异常列表是空的，或 NAME 列里没有设置页选中的那个模型名。

          

          
怎么处理：输入 ollama pull qwen2.5:3b 回车下载（约 2 GB，需要等几分钟，终端出现 success 才算完成）。也可以在应用「系统与隐私 → 推荐模型」里点「下载」，由应用自动完成。

        


        

          
4地址与端口是否被改过

          
回到应用「系统与隐私 → 本地模型」，看「Ollama 地址」输入框。

          

            
正常显示的是 http://127.0.0.1:11434，这是默认值，也是本机回环地址。

            
异常被改成别的端口（如 :11435）、去掉了 http://、或在末尾加了多余的路径。

          

          
怎么处理：直接改回 http://127.0.0.1:11434，点「保存」后再点「测试连接」。

        


        

          
5模型名是否完全一致

          
把第 3 步 ollama list 输出的 NAME 列，和设置页「模型」下拉框里选中的名称逐字对比。

          

            
正常两个字符串完全一样，包括冒号和后面的标签，例如都是 qwen2.5:3b。

            
异常任意一处不同：一个是 qwen2.5:3b、另一个写成了 qwen2.5（缺标签），或大小写不一致。

          

          
怎么处理：在设置页下拉框里重新选一次，确保选中的名称和 ollama list 里的完全相同；不要手动输入。

        


        

          
6是否只是首次加载慢

          
第一次点「测试连接」或开始审阅时，模型要把约 2 GB 的权重读进内存，需要一些时间。

          

            
正常等 10–30 秒后连接成功，之后每次都会很快。

            
异常等了超过 1 分钟仍失败，或反复超时。

          

          
怎么处理：先关掉其他吃内存的大应用（浏览器、视频剪辑等），再点一次「测试连接」。8 GB 内存优先用 qwen2.5:3b；换到 gemma3:4b 时每份合同会多等十余秒。

        


        

          
7内存是否够用

          
点屏幕左上角苹果菜单 →「关于本机」，看「内存」那一行的数字。

          

            
正常qwen2.5:3b 至少 8 GB；gemma3:4b 同样 8 GB 可跑，只是每份多等十余秒。

            
异常低于上述数值时，模型加载会很慢甚至直接失败。

          

          
怎么处理：在设置页把模型切换为 qwen2.5:3b，或临时关掉其他大型应用释放内存后再试。

        


        

          
8磁盘是否还有空间

          
模型需要临时空间才能加载，磁盘太满会失败。在终端输入下面这行查看系统盘可用空间：

          
df -h /

          

            
正常Avail（或中文系统的「可用」）列的数值大于 5 GB。

            
异常可用空间不足 5 GB，模型文件无法加载。

          

          
怎么处理：清理磁盘（清空废纸篓、删除大文件），然后退出 Ollama（点菜单栏小羊图标 → Quit Ollama）再重新打开，回到设置页点「测试连接」。

        


        
以上都排不通，可以直接关掉「模型增强」用纯规则模式审阅：规则 191 条照常全跑，只是金额、期限这类字段的抽取精度略低，不影响风险判定与导出。
