# 规则引擎评测（W2）

一条命令产出规则引擎在受控缺陷上的检出率、clean 对照告警、证据可回溯率、法条引用可解析率与耗时。

```bash
make eval        # 等价于 python3 -m eval.run_eval
```

输出：

- `eval/out/report.md`：人读报告
- `eval/out/metrics.json`：含逐案例明细与环境信息

评测只读本地语料，不访问网络，不调用模型（`mode=rule`）。

## 缺陷构造

`templates.py` 定义 34 类缺陷形态，每类对应一条内置规则：

- `inject`：在底稿末尾追加一段缺陷条款（如“验收合格后 90 日内付款”“租赁期限为二十五年”）。
- `remove`：删除底稿中命中规则标记的句子，制造条款缺失（如删除争议解决、转租、维修条款）。

同一模板会应用到所有适用的同类底稿，得到变体集合。以下组合会被排除：

- clean 对照本身已触发该规则：无法把命中归因于注入；
- 删除类模板在底稿中找不到对应条款。

## 指标口径

| 指标 | 定义 |
|---|---|
| 缺陷检出率 | gold 规则出现在该变体 findings 中的比例 |
| clean 对照告警 | 未修改底稿上的 findings 条数，按份平均 |
| 注入后新增非目标告警 | 变体 findings 减去 clean findings 与 gold 后的新增规则条数 |
| 证据可回溯率 | 注入类命中中，evidence 非空且能在变体原文中定位的比例 |
| 证据命中注入条款 | 在上述基础上，evidence 与注入句字符二元组 Jaccard ≥ 0.5 的比例 |
| 法条引用可解析 | 191 条规则的 basis 全部能在 KB 中取到法条的比例 |
| 耗时 | 单次 `evaluate()` 的中位数与 P95 |

## 结果（2026-11-18，commit 以报告为准）

- 语料 8 份，变体 54 个（注入 33、删除 21）
- 检出 53/54 = 98.15%（注入 32/33，删除 21/21）
- clean 对照 96 条，12.0 条/份（其中缺失类 54 条）
- 注入后新增非目标告警 2 条（R16、L06 各 1 条）
- 证据可回溯 32/32，证据命中注入条款 32/32
- 规则集法条引用可解析 191/191
- 单次 `evaluate()` P50 2.94 ms / P95 3.35 ms（耗时随机器负载波动，以每次 `make eval` 输出为准）
- 自动合同类型识别 5/8（人工标注为口径；两份租赁文本被识别为物业服务合同，保密协议被识别为劳动合同）

## 局限

- 缺陷形态按规则语义构造，gold 自检只保证“可判定”，不保证与真实合同中的缺陷分布一致。98.15% 是规则对已定义形态的覆盖，不是真实合同上的召回率，也不应外推为准确率。
- clean 对照的 96 条告警未逐条人工判定真伪；示范文本大量空白条款本身会触发缺失类规则。
- 新增非目标告警未区分是否由注入句合理连带触发，指标偏保守。
- 删除类规则的 evidence 按引擎设计为空，因此不纳入证据可回溯率。
- 本次未评测模型路径（`mode=agent` 的规则部分与本评测共用同一 `risks.evaluate`，但模型复核未纳入）。
